# Engine A — the adopted Laya checkpoint (docs/04 §2.1).
#
# Deliberately separate from requirements.txt. That file must keep working on a
# machine with no torch at all: the backup engine serves there, boot still
# succeeds, and tests/test_engine.py proves the fallback rather than skipping it.
# The Dockerfile installs this on top, and that image is the only deployment that
# is meant to run the checkpoint.
#
# torch is installed from the CPU wheel index by the Dockerfile *before* this
# file, so the PyPI CUDA build (~2.5 GB of libraries a free Space can never use)
# is never a candidate here. Versions are the pair the gate measurement was taken
# on: laya 0.4.8 with torch 2.14.0, transformers 4.57.6 (ml/laya_gate.py).
#
# laya requires: torch>=2.0.0, transformers>=4.48.0, safetensors>=0.4.0,
# huggingface_hub>=0.20.0, numpy>=1.20.0 — all satisfied by what is installed.
#
# The stack below is pinned to the environment the gate measurement and the
# real-checkpoint tests ran on (ml/laya_gate.py, tests/test_engine.py). Left
# unpinned, the first Render build pulled transformers 5.20.1 with
# huggingface_hub 2.2.0 — a major version the custom `laya` loader has never
# run against. The one number this image exists to reproduce must not drift
# with PyPI.
laya==0.4.8
transformers==4.57.6
huggingface_hub==0.36.0
tokenizers==0.22.2
safetensors==0.7.0
